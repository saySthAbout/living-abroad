# 보고서 섹션 순서 재배치안

> 중간보고 피드백 3순위: "시스템설계 → 기능명세서 → 프로세스 → 메뉴 → 화면설계" 순서 권고 대응.
>
> **한계 고지**: 업로드해주셨던 `Live Abroad 보고서.pdf`/`별첨.pdf` 원본은 이번 세션에 다시
> 첨부되지 않아 현재 파일 시스템에는 없고, 이전 검수 때 확인했던 실제 페이지·목차 번호를 정확히
> 재인용할 수 없는 상태입니다. 그래서 아래는 "각 섹션에 무엇이 들어가야 하는지 + 그게 이미 어느
> 파일로 존재하는지"를 기준으로 한 목표 구조 제안이며, 실제 보고서 목차에 이 순서대로 매핑하는
> 작업은 원본 편집 파일을 다시 열람하거나 공유해주셔야 정확히 도와드릴 수 있습니다.

## 제안 순서와 근거

피드백이 권고한 순서(시스템설계 → 기능명세서 → 프로세스 → 메뉴 → 화면설계)는 "이 시스템이
무엇으로 이루어져 있는가(설계) → 무엇을 하는가(기능) → 어떻게 흘러가는가(프로세스) → 사용자가
어디서 그걸 만나는가(메뉴) → 실제로 어떻게 보이는가(화면)" 순으로, 추상적인 것에서 구체적인 것으로
내려가는 흐름입니다. 현재 보고서는 이 순서가 뒤섞여 있어(피드백 원문 기준) 독자가 화면부터 보고
나중에 설계를 이해하게 되는 역순 구조라는 지적이었습니다.

| 순서 | 섹션 | 들어갈 내용 | 이미 존재하는 소스 |
|---|---|---|---|
| 1 | 시스템 설계 | 아키텍처 다이어그램, ERD(논리/물리), 기술스택 | `docs/Living Abroad 시스템 아키텍처.png`, `docs/Living_Abroad_논리_ERD.png`, `docs/Living_Abroad_물리_ERD.png`, `docs/Living_Abroad_Tech_Stack_Versions.md` |
| 2 | 기능명세서 | 요구사항 ID별 기능 정의(입력/출력/API/예외) | `docs/Living_Abroad_요구사항_4-8.md`, 이번에 작성한 `document_JinAhKwak/04_인증_기능명세서_draft.md`(인증 부분 보강) |
| 3 | 프로세스 | 업무 흐름도, CI/CD 파이프라인 | `docs/Living Abroad 업무 프로세스.png`, `docs/Living_Abroad_CICD_아키텍처.png` |
| 4 | 메뉴 구조 | 메뉴 트리, 권한별 접근 | `docs/Living_Abroad_메뉴구조도_구현현황.png` |
| 5 | 화면 설계 | 실제 화면 목업/스크린샷 | `docs/Living_Abroad_화면설계도_v1.0.html` |

## 적용 방법 제안

1. 위 5개 섹션을 보고서의 대분류 목차로 먼저 잡고, 기존에 써두신 본문 내용을 각 섹션에 맞춰
   잘라 옮기는 방식을 권장합니다(글을 새로 쓰기보다 재배치 위주).
2. 트러블슈팅, 테스트 결과, AI/RAG 고도화 내용은 이 5개 섹션 뒤에 별도 대분류로 두면
   피드백이 지적한 "설계→기능→화면" 흐름을 해치지 않습니다.
3. 목차·실제 페이지·Footer 페이지 번호 일치(3순위의 또 다른 지적사항)는 재배치가 끝난 뒤
   보고서 편집 툴에서 마지막에 한 번에 맞추는 것이 두 번 손대지 않아 효율적입니다.

원본 보고서 파일(편집 가능한 형태)을 다시 공유해주시면, 실제 현재 섹션 번호·페이지를 기준으로
"몇 페이지를 몇 페이지 뒤로 옮기라"는 구체적인 지시로 다시 정리해드릴 수 있습니다.
